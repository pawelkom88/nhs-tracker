# Deployment Guide — Know Your Wait

Know Your Wait is deployed as a fully static site to Cloudflare Pages via GitHub Actions.

## Overview

- **Hosting platform:** Cloudflare Pages (Direct Upload / static export)
- **Deployment trigger:** Automatic on successful completion of CI workflow on `main`, or manual trigger via GitHub Actions `workflow_dispatch`.
- **Artefact:** `apps/site/out` generated by Next.js static export (`output: 'export'`).
- **Analytics:** Cloudflare Web Analytics (cookieless, privacy-preserving, no cookie banner required).
- **Domain policy:** Custom domain must **never** include "NHS" (per [ADR-0004](./adr/0004-name-without-nhs.md)).

---

## 1. Cloudflare Account & Project Setup

1. Log in to the Cloudflare dashboard.
2. Navigate to **Workers & Pages** → **Create application** → **Pages** → **Direct Upload**.
3. Create a project named `know-your-wait`.
4. Note your Cloudflare **Account ID** (found on the right sidebar of the Cloudflare dashboard overview).

---

## 2. API Token Creation

Create a dedicated Cloudflare API token with least-privilege permissions:

1. In Cloudflare dashboard, go to **My Profile** → **API Tokens** → **Create Token**.
2. Select **Create Custom Token**.
3. Token settings:
   - **Token name:** `GitHub Actions Deploy - Know Your Wait`
   - **Permissions:**
     - `Account` → `Cloudflare Pages` → `Edit`
   - **Account Resources:**
     - `Include` → `All accounts` (or select the specific target account)
4. Create the token and copy the generated secret string.

---

## 3. Web Analytics Setup

1. In Cloudflare dashboard, go to **Analytics & Logs** → **Web Analytics**.
2. Click **Add site** and enter your production site hostname (e.g. `knowyourwait.org.uk` or `knowyourwait.service.gov.uk`).
3. Copy the JS snippet or extract the beacon token from `data-cf-beacon='{"token": "<ANALYTICS_TOKEN>"}'`.
4. This token is passed via `NEXT_PUBLIC_CF_ANALYTICS_TOKEN`.
5. Cloudflare Web Analytics is cookieless and does not track personal data across sites. No cookie consent banner is needed.

---

## 4. GitHub Repository Secrets

Configure the following repository secrets in GitHub (`Settings` → `Secrets and variables` → `Actions`):

| Secret Name                      | Description                                                | Example / Source              |
| -------------------------------- | ---------------------------------------------------------- | ----------------------------- |
| `CLOUDFLARE_API_TOKEN`           | Cloudflare API token with Pages Edit permission            | Created in Step 2             |
| `CLOUDFLARE_ACCOUNT_ID`          | Cloudflare Account ID                                      | Cloudflare dashboard overview |
| `NEXT_PUBLIC_CF_ANALYTICS_TOKEN` | Cloudflare Web Analytics site token (optional for staging) | Created in Step 3             |

---

## 5. Custom Domain Configuration

1. In the Cloudflare Pages project settings, go to **Custom domains** → **Set up a custom domain**.
2. Enter the domain name (e.g. `knowyourwait.org.uk`).
3. **CRITICAL GUARD:** In accordance with [ADR-0004](./adr/0004-name-without-nhs.md) and PRD branding rules, the site domain name and branding must **never** contain "NHS" (e.g. do not use `nhs-wait-times.co.uk` or `nhs-waiting.org`). The service is independent and descriptive.
4. Follow Cloudflare DNS verification instructions to activate SSL/TLS and DNS routing.

---

## 6. Security Headers & Redirects

Cloudflare Pages applies custom response headers and redirects statically at the edge from:

- `apps/site/public/_headers` (copied to `out/_headers` at build time)
- `apps/site/public/_redirects` (copied to `out/_redirects` at build time)

### Configured Security Headers:

- `Content-Security-Policy`: Disallows untrusted scripts and objects; allows self and Cloudflare Web Analytics beacon (`static.cloudflareinsights.com` and `cloudflareinsights.com`).
- `X-Content-Type-Options`: `nosniff`
- `Referrer-Policy`: `strict-origin-when-cross-origin`
- `Permissions-Policy`: Disables `geolocation`, `camera`, `microphone`.
- `X-Frame-Options`: `DENY`
- `Cache-Control`: Aggressive immutable caching for static assets (`/_next/static/*`), short/revalidate cache for HTML.

## 7. Post-Deployment Verification Checklist

After deploying to production or preview:

1. **Root page:** Verify `/` loads with status `200` and zero JS console errors.
2. **Specialty & Unit pages:** Verify `/england/trauma-and-orthopaedics/` and unit detail pages load properly.
3. **404 page:** Request `/non-existent-route` and ensure `/404` renders cleanly with status code `404`.
4. **Security headers check:**
   ```bash
   curl -I https://<your-domain>/
   ```
   Verify `content-security-policy`, `x-content-type-options`, `referrer-policy`, and `permissions-policy` headers are returned.
5. **No-cookie check:** Open browser DevTools → Application / Storage → Cookies. Confirm zero cookies are set.
6. **No-JS check:** Disable JavaScript in browser and verify all navigation and data tables function.
